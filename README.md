# DownloadSweeper

**Rust 驱动的本地文件整理 Agent。** 在浏览器中设置分类和读取权限，让 AI 生成计划，审查后再移动文件。支持下载目录整理、桌面整理和文件名重生。

## 特色

- **可视化分类**：节点图编辑目录、备注和具体文件示例；一级按扩展名分流，子级支持语义分类。
- **人机协作**：AI 浮窗只修改当前场景，建议逐项选择后合并；审查阶段也能用自然语言调整计划。
- **文件安全**：先规划、后执行，记录移动轨迹并支持校验恢复；清理候选须人工确认后才移入回收站。
- **逐格式权限与多模态**：分别授权文件名、元数据、文本/Office 切片、图片、视频最多三帧和 PDF 最多三页。
- **桌面目录保护**：已有文件夹默认不拆散，可整体分类或设为复用容器；快捷方式保留原位。
- **进度与费用可见**：并行批次、暂停续接、完整任务归档、输入/输出 token 和费用统计；默认任务预算 500,000 token。

## 安装与运行

### Windows 便携版 （[链接](https://git.tsinghua.edu.cn/rust-course/2026/agent/agent-zhupy25/-/blob/main/DownloadSweeper-0.1.0-windows-x86_64-20260906-180021-079.zip)）

解压整个 ZIP，双击 **Start.cmd**，自动打开浏览器。若提示缺少 `VCRUNTIME140.dll`，安装与包架构匹配的 Microsoft Visual C++ 运行库。

### 从源码运行

必要依赖：

| 平台 | 依赖 |
| --- | --- |
| Windows | stable Rust（MSVC）、Visual Studio Build Tools 的“使用 C++ 的桌面开发”及 Windows SDK（注：需要纯Rust以外的部分是因为需要调用 Windows 原生端口进行视频帧提取和PDF页面提取） |
| macOS / Apple Silicon | stable Rust（原生 arm64）、Xcode Command Line Tools（注：需要纯Rust以外的部分是因为需要调用 macOS 原生端口进行视频帧提取和PDF页面提取） |

在项目根目录运行：

```sh
cargo run --release --locked -p ds-web -- --open --config config.toml --data-dir .ds-data
```

Cargo 自动安装项目声明的 Rust 库，前端依赖已随源码提供。普通编译运行不需要 Python、Node.js、npm 或 FFmpeg，也无需复制项目或维护第二个目录。

默认地址为 `http://127.0.0.1:3187`；端口被占用时，在启动命令末尾加 `--port 3188`。Ctrl+C 停止服务；任务运行中优先点击 **暂停并保存**。macOS 原生适配已加入，仍需实机验收，详见 [平台说明](docs/MACOS.md)。

## 配置 API

1. 点击右上角齿轮 **模型与设置** → **连接与模型**，选择服务商，填写 **API Endpoint** 和 **API Key**。
2. 输入 Key 后自动查询模型；也可点击 **刷新模型**。选择模型，或在 **模型 ID** 中手动填写；按标注来源核对上下文长度。
3. 点击 **能力与速度**，设置上下文、输出上限、思考、视觉、并发和任务预算；点击 **费用**，选择官方价格预设或手动单价。
4. 点击 **保存设置** → **测试已保存的连接**。测试会发送一条简短请求并记录用量。

Key 保存在本机私有 `.env`，配置文件只记录环境变量名。改变 Endpoint 后需重新核对 Key；本地无鉴权模型可留空。官方价来自已核实预设，未知价格可手动填写；费用为估算，以服务商账单为准。

也可将 [config.example.toml](config.example.toml) 复制为 `config.toml`、[.env.example](.env.example) 复制为 `.env`：修改 `[llm]` 中的 `endpoint`、`model` 等参数，在 `.env` 的 `DS_API_KEY=` 后填写 Key，重启生效。已有配置不要覆盖，`.env` 不要分享。[详细接入](docs/MODEL_CONNECTIONS.md) · [计费说明](docs/PRICING.md)。

## 操作指南

### 下载目录或桌面整理

| 步骤 | 点击与设置 | 对应功能 |
| --- | --- | --- |
| 开始 | 首页选 **下载目录整理** 或 **桌面整理** → 填目录路径 → **开始整理** | 创建任务 |
| 00 扫描 | **扫描这个目录** → **下一步 · 读取权限** | 查看文件统计和实际目录图 |
| 01 权限 | 添加类别预设 → 修改扩展名、大小范围和读取权限 → **保存权限更改** → **下一步 · 目标结构** | 决定 AI 能读取什么 |
| 02 结构 | 编辑目录节点；AI 建议生成后点 **审查并合并 AI 建议** → 勾选建议 → **合并所选** → **下一步 · 生成计划** | 确定目标分类、备注和文件示例 |
| 03 计划 | 查看自动生成的规则计划；需要语义分类时点 **用 AI 批量分类** → **下一步 · 审查结果** | 按规则和 AI 建议规划具体去向 |
| 04 审查 | 比较 **整理前 / 整理后** → 展开 **具体操作清单**，搜索、翻页、勾选操作 → 勾选已审查 → **下一步 · 执行整理** | 每页 20 项，确认要执行的改动 |
| 05 执行 | **确认并执行整理** | 实际移动文件并保存轨迹 |

规则整理不需要 API Key。**只有最终执行才移动文件**；应用 AI 建议只更新计划与预览。

### 其他常用操作

| 想做什么 | 按钮与操作 |
| --- | --- |
| 调整目录树 | 展开节点参数，编辑名称、扩展名和备注；**选择具体文件**添加示例。节点底部 **＋** 新建子目录，展开/收起按钮控制分支；画布端口连接父子节点 |
| 保护已有文件夹 | **读取权限**页或 **实际目录与保护**页签 → 展开目录参数 → 将目录类型设为 **整体保护**；桌面模式默认如此 |
| 复用已有目录 | 将实际目录类型设为 **复用容器** → 在目标一级节点参数的 **复用现有目录**中选择它；保留原内容并接收新文件 |
| 随时问 AI | 点击 **AI** 浮窗 → 输入当前场景要求 → **发送给 AI** → 勾选并合并差异建议 |
| 调整审查结果 | 在 **告诉 AI，哪里还需要调整**中输入要求 → **生成修改建议** → 勾选建议 → **应用并更新整理后预览** |
| 使用多模态 | **模型与设置 → 能力与速度 → 视觉能力**；再在任务权限页为相应格式选择视觉预览或内容切片权限。Office 文本切片无需视觉模型 |
| 暂停与继续 | 运行中点 **暂停并保存**；在 **运行记录与检查点**找到任务，点 **从检查点继续** |
| 恢复整理 | 执行完成后点 **恢复本次操作** → **确认**；原路径冲突或文件变化时会报告，空分类目录保留 |
| 清理候选文件 | **文件删除建议**中设置筛选 → **更新本地筛选** → 勾选文件 → **移入回收站** → **确认移入回收站** |
| 撤销回收 | 点击对应批次的 **一键撤销此批回收**；先撤销回收，再恢复整理。回收站被清空后无法撤销 |
| 查看历史与用量 | **任务历史 → 打开任务 / API 明细**；任务页 **任务轨迹**查看执行过程 |
| 保存与加载归档 | **完整归档** → 完成后 **下载完整归档**；历史页点 **导入归档 / 旧会话**。完整归档导入后只读查看，重新整理需建立待扫描任务 |

### 文件名重生

首页选 **文件名重生** → 填路径 → **开始整理** → **扫描这个目录** → 设置并保存读取权限 → **下一步 · 命名范围** → 选择文件格式 → **下一步 · 生成计划** → **生成重命名计划** → 审查名称建议 → 勾选已审查 → **下一步 · 执行整理** → **确认并执行整理**。

### 使用试用文件

解压 500 文件试用包，首页路径选择其中的 `downloads`（400 个文件）或 `desktop`（100 个文件），按上述步骤操作。

也可在源码根目录使用 Python 3.11+ 生成样本：

```sh
python -B scripts/create_trial.py
```

脚本打印生成路径，所有内容均为合成数据，拒绝覆盖已有目录；EXE、LNK 和锁定文件为不可运行的占位样本。需要无费用体验 Agent 流程时，运行 `python -B scripts/serve_demo.py` 并打开其打印的地址；这是固定回复的本地模拟服务，不代表真实模型效果。macOS 将 `python` 换成 `python3`。

## 代码与技术组成

**核心业务逻辑和 API 主控流程均使用 Rust。**

| 目录 | 语言 / 技术 | 职责 |
| --- | --- | --- |
| `crates/engine/` | Rust、Tokio、reqwest、serde、BLAKE3 | 扫描、规则、权限、Agent 编排、并行与预算、预览、移动恢复、历史与计费 |
| `crates/web/` | Rust、Axum、SSE | 本地 Web 服务、API、实时进度、内嵌前端资源 |
| `frontend/` | JavaScript、React、React Flow、HTML/CSS | 页面、节点图、AI 浮窗与设置 |
| `crates/cli/` | Rust | 可选命令行入口，共用引擎 |
| `src-tauri/` | Rust、Tauri 2 | 可选桌面壳，共用 Web 后端 |
| 引擎中的 `*.m` | Objective-C、AVFoundation、CoreGraphics、Foundation | macOS 视频/PDF/废纸篓薄适配，由 Rust 调度；Windows 原生能力直接通过 Rust 调用 WinRT/COM |
| `crates/*/tests/`、`crates/dev/` | Rust、Boa（仅测试） | 自动化测试、凭据检查、维护者同步；前端测试执行实际 JavaScript |
| `scripts/` | Python、PowerShell、Shell | 可选试用数据、演示与打包，不承担产品运行时业务主控 |
| `docs/agent-tools/`、`*catalog.json` | Markdown、JSON | 工具说明、模型能力和价格预设 |

项目覆盖 Rust 核心、GUI、自定义模型、实时进度与打断、历史归档、token 与费用统计六项要求。运行 `cargo test --locked` 执行 Rust 测试，无需 Python 或 Node.js。开发检查见 [CONTRIBUTING.md](CONTRIBUTING.md)。

配置与任务数据保存在本机；保留 `.ds-data` 才能继续任务和恢复操作。分享程序时使用原始发布包，不附带 `.env` 或私人任务归档。详细边界：[多模态](docs/MULTIMODAL.md) · [检查点](docs/CHECKPOINTS.md) · [归档与回收](docs/ARCHIVES_AND_CLEANUP.md) · [文件校验](docs/FINGERPRINTS.md)。
