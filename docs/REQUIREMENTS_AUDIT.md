后续更新：用户确认真实 LLM 已连接实测，Apple Silicon 验收暂后置；本轮已实现完整归档、按上下文预算选择聊天历史和扩展清理候选，见 [使用说明](ARCHIVES_AND_CLEANUP.md)。以下表格保留实现前的审计快照，不应当作当前缺口清单。

核对日期：2026-09-05。对象是当前工作区源码；不是对所有旧便携包的认证。本次以代码审查、隔离浏览器操作、本地模拟 API 回归及分享检查为依据，没有调用真实付费模型，没有操作用户下载目录，没有进行 Mac 真机测试。

## 结论

主体产品方向已经落地：Rust 主控、专用六阶段整理流程、权限过滤、目录图、审查后执行、操作恢复、AI 协作与用量统计。无需为了符合早期描述而重新推翻架构或 GUI。尚不能宣称全部实现，主要差距在双端验收、完整会话归档、长对话记忆及清理建议覆盖。用户在本次核对中确认，浏览器下载记录同步早已放弃，不计入缺口或后续工作。

本次没有发现核心业务移出 Rust，或当前产品允许 AI 直接删除文件的原则性偏离。这里是有范围的审查结论，不是对任意输入和平台的绝对安全证明。

| 按文件类型设置 AI 读取权限 | 实现 | 从仅扩展名、本地处理，到文件名、元数据、视觉预览、文本/Office 切片；Rust 在证据发送前检查权限。选择 few-shot 不会越过对应文件权限。 |

## 六阶段流程及目录规则

| 原设想 | 对照结果 |
| --- | --- |
| 扫描 → 权限 → 目标结构 → 具体计划 → 审查 → 执行 | 已有统一状态机和下一步按钮；必须完成扫描、规则校验、计划及审查，才能执行。任务草稿从创建起持续保存，具体移动计划在规划阶段产生，符合逐步完善计划的目的。 |
| 根下一层只能简单扩展名规则 | Rust 校验强制执行，不仅是 GUI 限制；更深层允许简单或语义规则。 |
| 本地模板起步，AI 根据现有内容建议树 | 本地 `template()` 生成基础目录，目标结构阶段可使用文件检查摘要请求 AI 改进，建议显示差异并由用户合并。没有可用模型仍能使用本地规则。 |
| 实际已有目录可以拆散或视作整体 | 支持 normal/atomic/container，即可拆散、整体保护、复用容器；权限和目标结构阶段均能调整。目录类型调整使依赖计划失效，不重新扫描。 |
| 软件包、小文件素材库保护；复用已有整理目录 | 有本地识别提示、整体目录候选和容器映射；AI 可在适当场景建议类型，由用户合并。启发式不是所有绿色软件和素材库的完美识别器。Mac 含符号链接的 `.app` 整体移动仍受安全限制。 |
| 第三阶段 AI 自动改目录类型、继续细化结构 | 当前将规则设计和确认放在前面，第三阶段按已确认结构分类、生成具体计划；不让模型暗改目录类型和目标树。这是更稳妥的阶段边界，不列为必须恢复的旧行为。 |
| 尽量少移动文件 | 提供复用映射和保留已有位置的处理；未发现全局最少移动数量的优化算法或最优性保证。实际效果取决于用户确认的结构与映射。 |
| 对比整理前后、明确执行、可恢复 | 已有审查视图及计划差异，执行独立于 AI 规划；失败和取消保留执行记录及恢复入口。 |
| 不主动删除，只提出大文件/无用小文件建议 | 当前产品符合不主动删除。清理建议较窄：仅预选至少 1 GiB 的文件、低于 64 KiB 的 tmp/log，最多 100 条；AI 复核需用户点击，且只修改这些候选的理由，不会全面发现其他无用文件。 |

旧 `TrashBatchTool` 仍有回收站实现文本，但 `call()` 在非 dry-run 时提前拒绝，默认注册表也不提供该工具。不能据此断言当前 Agent 会删除文件。建议以后清理这段不可达分支和失真的工具说明，属于维护收尾，不是已证实的删除漏洞。

## GUI 老问题逐项复核

| 用户曾指出的问题 | 当前状态与本次证据 |

| 下一步停在当前步、当前步骤颜色错误 | 实测扫描完成后进入权限阶段；权限是当前高亮，扫描显示完成，目标结构未提前高亮。其余推进条件经状态机审查，未在本次逐一点击到真实文件执行。 |
| 当前目录树没有类型控件 | 节点“参数”展开后有三类选择；实测 Archive 从可拆散切为复用容器。代码仅调用 `set_directory`，不触发扫描。控件默认折叠，首次使用的可发现性仍可改善。 |
| 树布局混乱、自动排列展开全部子目录 | 当前固定从左到右、父节点按子树居中、曲线连线；实测四级目录保持第四级隐藏，自动排列没有展开它。布局回归通过。无需恢复早期任意拖动节点设计。 |

| 实际文件按格式、时间等排序分组 | 节点内提供名称、格式、最近修改、大文件优先及按格式分组；文件夹作为图节点，文件作为节点内列表。这是图式界面对资源管理器列表的合理替代。 |
| AI 浮窗不存在、不能收缩和移动、Emoji 难看 | 全局 Assistant 已接入；有拖动、收缩、最大化，使用 AI 字母。实测打开及最大化后没有另外的收缩入口球遮挡；拖动实现经代码核对。 |
| AI 改动不能直接合并 | 有红绿差异、勾选和“合并所选”；后端校验任务版本、场景及依赖，再原子应用。不是仅生成一段无法执行的建议文字。本次代码核对，没有使用真实模型生成树建议。 |

| 软件无法连接 LLM | 已有实际协议适配、发现、测试连接与错误反馈；本次本地 HTTP 回归通过 Chat Completions、Responses、Anthropic Messages。不能据此保证用户实际网络、代理、密钥、额度和每个供应商账号均可用。 |

## 后续追加要求

- 凭据迁移与可分享性：已采用私有 `.env` + 环境变量名；示例配置无秘密。本次源码扫描和指定 Windows ZIP 扫描通过。私有任务、环境文件和使用过的个人包不属于可直接分享范围；没有 Git 元数据，不能审核或证明历史提交已清除凭据。
- 并行与大上下文：工作流统一 Runtime，API 默认三路并行，可调 1–8；独立分类批次、目录检查及命名并行，局部证据三路并发。批次按上下文扩容，文件写操作仍顺序执行。有用量预留和检查点避免盲目重试；这有助于控制成本，不保证任意模型并发时费用绝对不增加。
- 工具约束：分类仅开放有界证据读取与提交分类，工具参数、文件范围、候选目录和权限由 Rust 检查；模型不获得任意文件系统写入。专用工作流比原有自由循环 Agent 更符合安全目的。
- 多厂商优化：有 DeepSeek、GLM、MiMo、LongCat、混元、GPT、Claude 的目录和协议分支；未知未来模型不保证自动完整适配。当前核对的是实现，不是重新认证官方模型列表与实时价格。
- 轻量多模态：有图片缩略图、Office OOXML 有界文本和视频少量帧；权限与模型能力共同约束，并转换为不同 API 的图像格式。Windows 原生解码有本地回归，Mac AVAssetImageGenerator 尚待 Mac 验收；FFmpeg 可选。PDF 正文、旧二进制 Office、HEIC、音频转写等不能统称已支持。

## 建议推进顺序

1. **完成可验证发布闭环**：在 Apple Silicon 上实际编译、权限/解码/文件恢复/打包验收；核对用户运行的包和当前源码版本。按用户实际供应商完成连接测试，明确失败原因。
2. **完善任务归档与记忆**：导出任务、轨迹和规则的版本化归档；把“只读查看历史”和“创建新任务继续整理”分开。聊天按上下文预算选择历史并保存摘要，避免固定 8 条截断。
3. **改善日常使用覆盖**：扩展可配置、按需 AI 复核的清理候选；提高目录参数入口可发现性，验证大目录图性能；显示模型能力和价格数据的新鲜度。
4. **清理兼容代码**：移除已禁用的旧写入/回收站分支及过时说明，让代码边界更容易核对；保留当前 Rust 主控和审查后执行的架构。
