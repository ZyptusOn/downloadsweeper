# R4：实时进度、暂停与状态还原

浏览器工作台的长任务提供实时进度和“暂停并保存”。暂停请求先落盘，再通知工作线程停止；界面显示“正在保存”，到达安全边界后显示暂停结果。“运行记录与检查点”可在刷新或重启后查看，并对仍有效的记录选择“从检查点继续”。不会在启动时自动移动文件或重发模型请求。

## 保存什么

- 运行记录：运行 ID、所属任务、操作类型、允许的参数、进度、状态、保存时间、任务版本和模型配置摘要。模型配置只保存散列，不保存 API key。
- 业务状态：完整任务快照、已完成的分类批次、目录检查摘要、重命名结果、清理复核批次和实际用量。
- 文件操作：已有的移动/恢复意图日志、每项操作状态和指纹。
- 模型回答：在同一次运行的私有目录内保存完整回答与 usage 的校验封装，先持久化回答，再确认用量写入。崩溃发生在回答到达与业务结果提交之间时，能够重放回答，避免重复请求和重复统计。

运行元数据约每 0.75–1 秒保存一次；业务检查点在各自的提交边界同步保存。进度通过 SSE 推送，并以每秒心跳和轮询补偿等待及事件丢失。临时 JSON 写入后 `sync_all`，再原子替换；Unix 还同步父目录。校验失败的检查点禁止恢复，保留原记录供检查，不阻止其他任务打开。

## 各操作的恢复边界

| 操作 | 暂停和继续方式 |
| --- | --- |
| 扫描、扩展名规划、本地清理筛选 | 保留原有完整快照。未提交的本地阶段重新计算，不发布不完整目录或计划，不发起 API 请求。不是逐文件扫描游标续传。 |
| AI 分类、目录检查、重命名 | 复用已完成的业务检查点；同一运行中已经保存的相同请求回答可以重放。模型、权限、规则或任务版本变化时拒绝旧检查点。 |
| AI 清理复核 | 按批提交，已复核候选不会再次发送，包括模型建议保留、未给出新理由的候选。 |
| 执行文件移动 | 继续前先核对意图状态和已移动文件的指纹，仅执行剩余 pending 项。存在失败项、路径歧义、文件变化或目标被占用时停止，不覆盖、不删除。 |
| 恢复文件 | 保留已恢复项；中断意图先检查两侧位置和指纹，再处理剩余项。 |
| 完整归档导出、导入 | GUI 使用后台任务。分块读写、可暂停，临时文件不作为完成结果发布。导入输入保存一次；继续重新校验。导出结果保存在本机，重启后仍可下载。 |
| 聊天、连接测试 | 上下文、回答和用量保存；单次远程生成不提供服务端断点续传。需要重发时由用户手动发起新请求。 |

没有收到完整回答及 usage 的调用保持 `pending_calls`，预算预留不释放，相关 AI 运行不提供自动继续。已经完整落盘的回答能够在启动时补回 usage；仅有请求记录不能推测费用或伪造回答。新运行与导入任务使用不同的回答缓存范围。

“暂停”是协作式安全停止，不是任意 CPU 指令或系统调用的零延迟内存冻结。正在完成的原子文件操作、磁盘同步或有界 JSON 校验需到达安全边界。扫描目录可能在暂停期间变化，因此继续时重扫本地阶段比使用过时的目录游标更可靠。

## 数据与接口

运行记录位于任务数据目录 `jobs/<运行ID>.json`；归档输入和导出结果分别在 `jobs/inputs/`、`jobs/results/`。模型回答位于 `<任务ID>/responses/<运行ID>/`。这些都是私有运行数据，不进入分享包；可能含模型回答、路径或对话内容。任务归档仍是完整 Task 与轨迹备份，不作为跨机器恢复本机运行记录的可执行指令。

GUI 使用 `/api/jobs` 查看记录，`resume_job` 继续运行，`cancel` 暂停，`archive_export` / `archive_import` 启动归档任务，`/api/jobs/<ID>/result` 读取已完成结果。旧同步归档接口保留用于兼容；新版 GUI 不再通过它启动导入导出。CLI 保留 Ctrl+C 和原有业务检查点；持久化运行列表与继续按钮目前由 Web 工作台提供。

```text
cargo test -p ds-engine --test job_recovery

```
