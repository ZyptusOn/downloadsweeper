# 恢复指纹格式

指纹用于移动后的身份核对，不是备份。匹配后仍要确认原路径空闲，才允许恢复移动。

| 记录前缀 | 读取规则 |
| --- | --- |
| 无前缀的 64 位十六进制 / `sha256:` | 旧版 SHA-256，全量读取 |
| `blake3:` | BLAKE3，全量读取，包括已有的大文件及目录记录 |
| `blake3-adaptive-v1:` | 不超过 16 MiB 全量读取，更大的文件抽样 |
| `blake3-adaptive-v2:` | 不超过 1 MiB 全量读取，更大的文件抽样（新操作默认） |

新独立小文件沿用 `blake3:`。新大文件和整体目录使用 `blake3-adaptive-v2:`；目录内每个文件独立判断阈值。目录结构、相对路径、文件大小及空目录均参与校验，不拆散整体目录。

## 分段规则

新 v2 阈值为 1 × 1024 × 1024 字节，旧 v1 阈值保持 16 × 1024 × 1024 字节，只有严格大于对应阈值才抽样。两版均为每段 64 × 1024 字节，共五段，总读取量 327680 字节（320 KiB）。对于长度为 `L` 的文件，第 `i` 段起点为：

```text
floor((L - 65536) × i / 4), i = 0, 1, 2, 3, 4
```

因此覆盖开头、约四分之一、中间、约四分之三和结尾。指纹还包含文件长度、修改时间、每段偏移和长度。使用文件句柄读取元数据，抽样结束后再次核对大小与修改时间，避免记录正在变化的文件。

大小与修改时间可帮助发现未抽样区域的通常修改；如果修改时间被保留或还原，则可能漏检。匹配只表示这些信息和抽样片段一致，不能宣称整个大文件内容相同。界面和恢复确认框会说明此限制。

## 编码与兼容

所有摘要为 32 字节，保存为十六进制字符串。版本标记是协议的一部分，禁止更改已发布版本的阈值、段数或段长；策略变化必须使用新版本标记。本次门槛调整使用 v2，因此旧目录记录中 1–16 MiB 的文件仍按 v1 完整校验。

旧全量算法保持原序列化：独立文件直接计算内容摘要；目录按名称排序遍历，包含根节点。每项依次写入相对路径 UTF-8 字节长度（u64 小端）、路径字节、目录标志（1 为目录，0 为文件）；文件再写入长度（u64 小端）和完整内容。

两版使用 BLAKE3，并先写入 `DownloadSweeper adaptive fingerprint v1` 或 `DownloadSweeper adaptive fingerprint v2` 加零字节，再写入根类型标志。除此域标记和阈值以外，两版编码相同：目录项沿用上述路径、类型、文件长度字段。每个文件接着写入抽样标志（0/1）及长度（u64 小端）。全量文件随后写完整内容；抽样文件写入修改时间和五段记录。

修改时间编码为 Unix epoch 前后标志（早于为 1，否则为 0）、距 epoch 的绝对秒数（u64 小端）及纳秒部分（u32 小端）；每段记录为偏移（u64 小端）、长度（u64 小端）、内容。目录相对路径保持当前系统的分隔符，恢复仅在原文件系统的同卷目录内进行。

恢复和中断核对由保存的前缀选择算法，绝不把旧全量记录当作抽样记录，也不在升级时重新生成用户文件的指纹。未知版本、缺失或格式损坏的摘要会停止操作。
