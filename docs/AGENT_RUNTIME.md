# Agent 与工具运行时

GUI 和 CLI 共用工作流。所有工作流模型请求经过 `ai_runtime::Runtime`，统一处理上下文准入、并行额度、任务预算、取消、超时和用量记录；HTTP 客户端复用连接池。请求响应体限制为 8 MiB，不跟随重定向。

## 执行与持久化

Web 长任务的运行记录、暂停请求和恢复入口已持久化；归档导入导出、本地清理筛选进入后台运行。完整回答与 usage 在同一运行范围内缓存，可恢复“回答已到达但业务检查点未提交”的窗口。详见 [R4 检查点机制](CHECKPOINTS.md)。

只读工作使用不可变任务快照。工作线程通过带确认的事件通道提交结果，只有协调器修改任务和写入 TaskStore：先保存请求预留，再允许发送 HTTP；收到响应后先保存真实用量，再将结果交给业务校验。分类和重命名全部完成且通过校验后，才统一替换待审查操作。

并行数默认为 3，可在设置中调整为 1–8。分类的独立批次并行；目录检查的不同类型并行，同一类型的摘要依次累积；重命名按文件并行。目录设计、聊天等有前后依赖的单次请求保留顺序。文件执行、恢复和碰撞分配继续串行，不交给模型工具执行。

分类默认每批最多 256 个文件，可设置 1–1024。批次在候选节点、视觉证据和输出额度约束下，二分寻找能够容纳的最大文件数。初始文本预算随上下文增长，最多 1 MiB；工具对话最多 2 MiB。输入估算采用保守字节计数，并包含工具定义、续接数据及图像预留，不是精确 tokenizer，也不作账单用量。正文与图像仍受读取权限和证据上限约束。

## 预算与续接

同一任务的并发请求共享预留账本，防止多个请求各自花掉同一笔剩余额度。服务返回的 usage 才计入实际用量。超时、取消或缺失完整 usage 会保留 `pending_calls` 预留，在 UI 单独显示；重启后仍计入准入，不自动重试不确定请求。明确的 HTTP 4xx 拒绝会释放预留，保留错误事件。预留是保守估算，不能保证与供应商实际账单完全一致。

分类逐批保存，目录检查逐摘要保存，重命名逐文件保存检查点。一个工作失败后停止排队请求，仍接收已在途请求的用量和可验证结果。继续时仅补未完成工作；扫描快照、权限或影响结果的模型配置改变会使对应检查点失效。旧 Task 导入和从归档创建新任务时清空可执行计划、检查点与未确认预留，并要求重新扫描；完整归档以只读形式保留原始状态和全部轨迹。实际发生的历史调用记录仍保留。

## 工具与文件边界

分类只提供 `read_file_evidence` 和 `submit_classifications`。共享协议检查约束工具白名单、唯一调用 ID、有界对象参数与单轮调用数；场景检查进一步限制文件引用、候选节点和权限。每批工具轮次默认 12，可设置 1–32。目录设计、命名和聊天不获得任意路径写入工具。

文本与图像证据通过验证后的文件句柄读取，读取前后检查快照；Windows 读句柄限制并发写入和删除，并验证实际打开的路径仍在根目录内。图像解码还有尺寸和内存上限。Windows 视频优先使用系统原生解码，独立子进程整体限 8 秒；FFmpeg 为可选后备。两个后端都在父进程保留只读句柄期间运行，受输出上限、取消与超时控制。系统解码器及路径接口不能视为对恶意并发文件系统修改的完整沙箱。

旧 Agent、独立分类/命名管线、工具注册表和旧计划系统已移除。GUI、CLI 与 Tauri 统一使用 `workflow`、`workflow_ai` 和 `ai_runtime`。生产文件修改只能通过经过审查的安全执行流程，使用无覆盖移动、指纹、预写记录和恢复。

## 验证与性能范围

在本地模拟 API 每次固定延迟约 220 ms 的回归中，120 个文件的六批分类约由串行 1.77 秒降为三路并行 0.80 秒；1M 上下文用例将 240 个长文件名装入一次请求，超过旧 24 KiB 固定限制。这是调度回归结果，真实速度取决于服务商并发限制、延迟、输出长度和文件证据处理。

源码目录可运行：

```powershell
cargo test --workspace --exclude ds-tauri --locked
cargo build -p ds-web --locked
cargo test --locked -p ds-web --test runtime
cargo test --locked -p ds-web --tests
cargo test --locked -p ds-web --test model_connections
cargo test --locked -p ds-web --test frontend
cargo test --locked -p ds-dev --test share
cargo run --locked -p ds-dev -- verify-share
```

运行时回归使用独立临时配置和本地模拟服务，验证并发上限、上下文扩容、检查点续接、预算预留、超时持久化、拒绝释放与导入失效。协议回归覆盖 Chat Completions、Responses 和 Anthropic Messages；不代表全部服务商都已实网生成验证。便携包由 `scripts/package.ps1` 先扫描可分享源码，再扫描发布目录和 ZIP，不包含私有 `.env`、任务数据或个人配置。

内容预览与 API 使用不同的并发资源：本地 3 个工作位，阻塞读取/解码不占用异步线程；批次读取并行且结果保持顺序。API 请求的并发上限、批次规模、失败停止与预算预留规则保持一致。视频与 Office 的权限、采样和接口约束见 MULTIMODAL.md。
