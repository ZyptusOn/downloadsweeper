# 完整归档、聊天历史和清理建议

## 保存与查看归档

GUI 的导入、导出现在是可暂停后台任务；导出完成后在“运行记录与检查点”下载，重启后结果仍保留。见 [暂停与还原](CHECKPOINTS.md)。

工作台和任务历史中的“完整归档”导出一个版本化 JSON，包含完整 Task、全部 JSONL 轨迹记录、导出时间和 BLAKE3 完整性校验。Task 中的扫描快照、目录规则、权限、操作及恢复状态、消息、建议、调用费用、检查点和待确认用量均保留。归档正文保存在 `payload` JSON 字符串中，避免浏览器重新保存时改变整数精度或浮点表示；界面解析展示但下载时保留原文。不把配置或 `.env` 密钥加入归档，也不打包下载目录中的原文件；对话、文件路径及轨迹本身可能含私密信息，因此归档应当作为私有备份保存。

运行中的任务需要先完成或停止再导出，避免任务快照和轨迹不一致。损坏的轨迹行不会静默跳过；单份归档上限为 30 MiB，超限会明确失败，不截断数据。校验只能发现损坏或修改，不是来源认证。

历史页“导入归档 / 旧会话”有两种兼容行为：

- 新归档存入任务数据目录的 `archives/`，在“只读归档”查看消息、文件操作、工作轨迹及完整任务 JSON。即使原目录已不存在，也能查看；它不会进入文件执行或启动恢复流程。
- 旧 Task JSON 仍可导入为新任务，需要重新扫描；旧文件本来没有携带的轨迹无法补回。

只读归档中的“创建待扫描任务”允许选择本机目录，复用规则和对话；新任务清空可执行计划、检查点和未确认预留，重新扫描、规划、审查。原归档和其中的待确认费用保持不变。归档查看不是导入一份可信的可执行恢复指令；本机原始任务仍可走原有安全恢复流程。

CLI：

```text
ds export <任务ID> <文件.json>
ds import <文件.json>
ds archives
ds archive-show <归档ID>
ds resume <归档ID> [本机目录]
```

需要编辑旧格式任务 JSON 时用 `ds show <任务ID>` 输出 Task，再用 `ds update`；`export` 现在输出归档封装，不再是裸 Task。

## 浮窗历史

取消固定的最近 8 条限制。Rust 根据配置上下文、模型已知输入上限、剩余任务预算及输出预留，按保守字节估算选择同场景历史，总输入选择上限为 2 MiB。容纳得下时携带全部历史；否则保留连续的近期消息，并用少量明确标注、每条最多 240 字符的早期用户原文摘录补充最初意图。摘录不是 AI 生成的语义摘要，旧要求可能被后续要求替代；当前场景和最新指令优先。

没有增加摘要请求。扩大历史输入可能增加单次输入 token，但仍经过统一任务预算检查；不会假称长对话完全没有额外输入成本。场景隔离保持不变，不把其他页面的对话混入当前可编辑场景。超出容量的消息仍完整保存在本地，浮窗显示上次请求的完整历史条数、摘录条数及未携带数量；轨迹记录 `chat_context_selected`。

## 清理建议

整理完成后，即使没有候选也显示筛选面板。支持大文件、临时/备份文件、未完成下载、旧安装/可执行文件、旧压缩包/镜像、疑似副本和空文件。可选择类别、大小门槛、未修改天数及候选数量，设置随任务归档。默认 1024 MiB、180 天、最多 200 条，最多可选 500 条；界面显示匹配总数，不会把截取后的数量当作全部候选。

筛选只依据扫描快照，不读取正文，不遍历下载目录外的位置。小于 64 KiB 的 tmp/log 延续原有提醒；旧安装、压缩包、未完成下载、空文件及其他临时/备份格式使用未修改天数条件。名称去除常见副本编号后相近且同大小只表示“疑似副本”，没有做内容去重。未修改不等于未使用；整体保护目录内部文件排除。已移动文件显示整理后的路径。

“让 AI 复核候选”最多每批 32 项，并受上下文、权限、任务预算、取消和超时约束。只发送权限允许的名称/元数据，不发正文或图像；仅扩展名权限的文件不发送，文件发生变化也不发送。每批校验模型只能引用本批候选，成功后保存理由和实际用量；失败或取消保留已保存结果，不自动重试。再次主动点击会重新复核当前候选，属于新的付费请求。

CLI 可用 `ds cleanup <任务ID>` 刷新本地候选，`ds cleanup <任务ID> --ai` 请求复核。GUI 的“文件删除建议”支持勾选候选、查看确认清单后移入系统回收站；AI 工具不能调用回收入口，没有永久删除或清空回收站接口。

## 回收与一键撤销

回收前按扫描大小、修改时间、受保护目录与整理后路径校验整批选择，再对所选文件做全量 BLAKE3 校验。仅允许本任务的候选文件，不接受任意路径或目录。遇到文件变化会停止；回收与撤销使用后台进度及持久记录。

每个文件先进入根目录中的唯一 `DownloadSweeper-Recycle-<UUID>` 恢复文件夹，再将这个文件夹移入系统回收站。内部保留原文件名；唯一标识用于避免同名误恢复，也便于进程中断后查找。暂存目录不参与新任务扫描。系统不支持回收时停止，文件与恢复记录保留，不能转为永久删除。

点击“一键撤销此批回收”先从系统回收站取回，再校验文件内容并无覆盖移回整理后的路径。撤销后才可继续“恢复本次整理”。同名冲突或文件改变会报告具体原因，其他可恢复项目仍可继续。若回收站被清空或文件被外部移走，不能保证恢复；不要删除任务数据。回收记录随完整归档保留，但从归档创建新任务时清空执行资格，不能借导入归档操作别的回收条目。

Windows 使用 IFileOperation 的回收标志与系统回收站条目标识；macOS 使用 NSFileManager 的原生废纸篓接口，恢复采用无覆盖移动。Mac 代码需在实机验收。回收完成的目录与文件应从系统回收站恢复，不要仅删除程序内的记录。
