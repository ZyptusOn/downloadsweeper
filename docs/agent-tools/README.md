# 批量分类工具协议

目录设计与文件归类是两种不同任务。此阶段的模型只判断已有分类的语义归属；扫描、类型路由、权限检查、批次组织、结果校验、碰撞处理、计划持久化、文件移动及恢复均由 Rust 控制。

## 边界与调用顺序

1. Rust 先完成规则计划。整体保护目录的内部文件、复用目录内部文件、下载中的文件、无读取权限的文件，以及没有语义分类候选的文件不交给模型。
2. 按相同的候选节点集合分组，跨文件类型的简单规则仍是硬约束。模型收到短文件引用、获准的元数据，以及去重后的节点名称、父子关系、备注和示例引用。首轮不自动读取文件正文。
3. 使用 Chat Completions、Responses 或 Anthropic Messages 的原生工具协议，工具定义和运行时校验同时约束输入。普通说明文字不视为分类提交，也不执行模型生成的代码。
4. `read_file_evidence` 按需读取授权内容；`submit_classifications` 提交完整的批量映射。工具错误会作为 `role=tool` 返回，模型默认最多有 12 轮处理本批（设置范围 1–32），避免无界循环。
5. 独立批次按配置并行（默认三路），每个已验证批次由唯一协调器持久化到任务的 `classification`，并写入轨迹。所有批次完成后，一次性更新 `operations`。期间原计划不被覆盖；失败或取消后，从已完成批次继续，不重复发送已完成批次。
6. 实际移动依旧由用户在审查后确认 `execute`，调用 `safe_fs::execute`：固定的来源/目标、无覆盖检查、内容指纹、预写日志和恢复。模型的分类工具集中没有 `execute`、终端、删除或目录树编辑工具。

## 动态批次

24 不是模型或协议限制。本实现默认文件数上限为 256，用户可设置 1–1024。Rust 按实际上下文体积、潜在证据体积、候选节点集合及输出额度缩小批次：初始文本上限随上下文增长，最多 1 MiB，工具对话文本最多 2 MiB，且必须满足用户配置的上下文长度。估算只用于准入，不当作实际 token 用量。

有图像证据能力的待分类文件每批最多 4 个，为图片和视频帧留出预算；工具一次读取最多 8 个文件、4 张图像，本批最多 8 张图像（含示例）。文本切片最多 1024 字节，并服从用户更小的授权上限。过大的节点说明不会被静默删去；单文件批次仍装不下时，会报明原因，让用户调整上下文、输出额度或该分支说明。

分类默认不启用思考，可在分类操作区单独开启。此选项不改变目录设计和聊天的模型设置。文件数对应的输出估算只用于批次准入，不限制模型实际回答长度。标准和思考模式都使用用户配置的「单次输出上限」，仅在剩余任务预算或上下文空间不足时下调；轨迹同时记录设置值、实际请求上限、输入估算及下调原因。

每次响应使用服务返回的输入/输出 token 精确计费。若服务返回截断标记，整次回答不参与分类，保留已完成批次和原计划；用户点击继续后重新处理未完成批次。截断错误会区分设置上限与预算/上下文约束；没有完整 usage 的超时或取消不能计作零用量，不自动重试不确定请求。

## 校验与检查点

分类必须覆盖整批，每个文件恰好一次；只接受本批给出的节点 ID 或 null。Rust 再检查每个文件的实际类型路径、简单规则、读取授权和扫描快照，计算最终目标并保留已有操作 ID 与勾选状态。null 保留原计划目标，不猜测内容。

恢复键覆盖扫描快照、权限、目录树、模型服务/模型名、协议、系统指令版本、温度与工具轮次、多模态与上下文/输出配置、分类选项和批次分界。修改这些因素后重建检查点；返回规划/审查或修改操作勾选不清空有效分类。已完成的分类再次运行视为重新分类。导入任务要求重新扫描，不直接采信旧分类结果。

轨迹事件包含请求文本字节数、图像数、耗时、工具名称与参数、工具结果、批次开始/完成和最终计划生成。正文只出现在明确调用读取工具后的本地轨迹中；密钥不进入事件。UI 展示已分类文件数、批次、当前分支和等待秒数，而不是用心跳冒充文件完成。
